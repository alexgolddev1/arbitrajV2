# Сервис трейдера: исследовательская симуляция

Трейдер получает от скринера уже зрелую возможность. Порог непрерывной жизни (по умолчанию 15 секунд) проверяет только скринер; трейдер этот таймер не дублирует. Сервис не выставляет реальные ордера и не выполняет ввод или вывод средств.

## Цикл симуляции

1. Сигнал проверяется на свежесть, формат, торговые комиссии и маршрут.
2. Покупка моделируется по лучшему ask доступного spot-стакана. Количество ограничивается USDT-балансом и видимым объёмом ask на этом уровне. Эта упрощённая модель сохранена в записи сделки.
3. Из доступного баланса атомарно списываются затраты покупки, комиссия покупки и комиссия перевода в USDT. Купленное количество уменьшается на комиссию покупки и перевода, если они списываются в базовом активе. Монеты позиции хранятся отдельно от доступного баланса.
4. После плановой задержки сервис получает новый стакан bids и симулирует рыночную продажу уровнями. Каждая фактически исполненная часть и выручка фиксируются один раз; повторная проверка видит только остаток. Продажа может дать прибыль или убыток.
5. Если после лимита ожидания остаются монеты, позиция сохраняется в статусе `open` с последней доступной оценкой. Остаток не обнуляется и не возвращает затраты в доступный баланс.

Баланс `trader_account.balance_usd` — доступные USDT. Открытые позиции, удержанные монеты, исполненные количества и резервы моделирования хранятся в `trader_training_settlements`. Новые поля добавляются миграцией; старые сделки сохраняются с маркировкой `legacy` и задним числом новой модели не приписываются.

## Комиссии

Запросы персональных торговых ставок Binance, Bybit, OKX и MEXC используются только для чтения. Для подписанных запросов Binance/MEXC передаётся API-ключ в заголовке. Для OKX знак приводится к соглашению приложения: положительное значение — расход, отрицательное — rebate. Скидка Binance за BNB не применяется, пока наличие достаточного BNB не подтверждено.

Если API-комиссия недоступна, задайте для нужной биржи `TRADER_<EXCHANGE>_TAKER_FEE`, например `TRADER_BINANCE_TAKER_FEE=0.001` для 0,1%. Источник ставки и применённые buy/sell ставки сохраняются в сделке. Когда нет ни ставки API, ни явно заданной ставки, новый вход отклоняется/повторяется без нулевой подстановки.

Модель валюты комиссии покупки настраивается для каждой биржи: `base` уменьшает полученное количество монет, `quote` добавляет расход USDT. По умолчанию стоит `quote`; это допущение модели, если фактическое списание аккаунта недоступно.

## Маршрут и время перевода

Состояние маршрута сохраняется отдельно: `confirmed`, `unconfirmed` либо `disabled`. Совпадения сети разрешены только для точных известных названий; неизвестные имена не объединяются, Ethereum и Arbitrum — разные сети. Совпавший контракт актива между биржами подтверждает идентичность; если данных контракта нет, маршрут помечается как предполагаемый. В демо предполагаемые маршруты включены по умолчанию; явно отключённый ввод/вывод отклоняется. Его обход можно отдельно включить, но для исследовательских результатов это рискованное допущение.

Комиссия перевода берётся из API кошелька биржи или из `TRADER_TRANSFER_FEE_AMOUNT` вместе с `TRADER_TRANSFER_FEE_CURRENCY`. Если комиссия и валюта не определены, сделка не открывается. Неизвестная валюта комиссии не конвертируется в USDT.

По умолчанию используется фиксированная задержка `TRADER_FIXED_TRANSFER_SECONDS=300`. Для воспроизводимой случайной модели включите `TRADER_RANDOM_TRANSFER_TIME=1` и установите `TRADER_TRANSFER_RANDOM_SEED`; модель и seed сохраняются в записи. Сеть выбирается по конфигурации/проверенным данным, а не по минимальному случайному времени.

## Прибыль и допущения

Для входа рассчитывается продажа всего остатка после комиссий по глубине bids, а не по одному лучшему bid. Прибыль до резерва и после него сохраняется отдельно. Резерв на изменение цены (`TRADER_PRICE_MOVE_RESERVE_PERCENT`) используется только при решении об открытии, повторно как расход не списывается. `TRADER_MIN_NET_PROFIT_USDT` задаёт минимальную прибыль после резерва.

В тренировке после задержки перевода выставляются виртуальные уровни выхода: take-profit берётся из `sell.price` исходного JSON-сигнала, stop-loss рассчитывается как заданный процент ниже фактической цены покупки. TP моделируется лимитной продажей по bids не ниже заданного уровня; SL срабатывает по текущему bid и моделируется рыночной продажей. Пока цена между уровнями, позиция остаётся открытой и периодически перепроверяется. В рабочем режиме выставление ордеров на бирже не реализовано.

Пример: баланс 100 USDT, ask 10 USDT, видимая ликвидность покупки 20 монет, taker 0,1% в котируемой валюте, комиссия перевода 0,02 монеты. Расчёт берёт до `100 / (10 × 1.001) = 9.99000999` монеты. Стоимость покупки около 99,9001 USDT, торговая комиссия около 0,0999 USDT; после перевода остаётся около 9,97000999 монеты. Если bids дают 9,95 USDT за первые 5 монет и 9,90 за остаток, ожидаемая выручка около 98,9531 USDT. Продажная комиссия 0,1% — около 0,09895 USDT; комиссия перевода 0,02 монеты отдельно учитывается как удержание актива. При резерве цены 0,25% от покупки (около 0,24975 USDT) ожидаемая прибыль до резерва около −1,1459 USDT, после резерва около −1,3956 USDT — симуляция не входит в сделку.

Демо остаётся приближением: ask-покупка моделируется только на лучшем уровне; валюту торговой комиссии покупки надо задать явно; контракт без доступного адреса не подтверждает идентичность; задержка — профильная, а не фактическая; при моделировании не учитываются динамические ограничения точности и минимального ордера, проскальзывание покупки, изменение комиссии во время задержки и стоимость остатка как реализованная прибыль. Неизвестные данные не подменяются случайной сетью или нулевой комиссией.

## Настройки

См. корневой `.env.example`. Основные параметры:

| Переменная | Значение по умолчанию | Назначение |
| --- | ---: | --- |
| `TRADER_TRAINING_MODE` | `1` | Только виртуальная симуляция. Реальный режим остаётся не реализованным. |
| `TRADER_INITIAL_BALANCE_USD` | `100` | Начальный баланс при первом создании счёта; существующий баланс сохраняется. |
| `TRADER_<EXCHANGE>_TAKER_FEE` | пусто | Запасная комиссия, применяется только если API не дал ставку. |
| `TRADER_<EXCHANGE>_BUY_FEE_CURRENCY` | `quote` | Модель списания buy-комиссии: `base` или `quote`. |
| `TRADER_ALLOW_UNCONFIRMED_ROUTE_DEMO` | `1` | Разрешить и явно помечать предполагаемые маршруты в демо. |
| `TRADER_ALLOW_DISABLED_ROUTE_DEMO` | `0` | Не обходить явный запрет ввода/вывода. |
| `TRANSFER_NETWORK_MAP` / `TRADER_TRANSFER_NETWORK` | карта из `.env.example` / пусто | Явное соответствие тикера или фиксированная сеть для демо-маршрута. |
| `TRADER_TRANSFER_FEE_AMOUNT` / `TRADER_TRANSFER_FEE_CURRENCY` | пусто | Запасная комиссия сети и валюта её удержания. |
| `TRADER_FIXED_TRANSFER_SECONDS` | `300` | Воспроизводимая задержка по умолчанию. |
| `TRADER_RANDOM_TRANSFER_TIME` / `TRADER_TRANSFER_RANDOM_SEED` | `0` / пусто | Включить воспроизводимую случайную модель. |
| `TRADER_MIN_NET_PROFIT_USDT` | `0` | Минимальная прибыль после ценового резерва. |
| `TRADER_PRICE_MOVE_RESERVE_PERCENT` | `0` | Процент резерва на изменение цены; не является комиссией. |
| `STOP_LOSS_PERCENT` в `main/treider/config.py` | `0.5` | Стоп-лосс в процентах ниже фактической цены покупки; `0` ставит его на цену входа. |
| `TRADER_MAX_LOSS_PROFIT_RATIO` | `0.25` | Максимальный реализованный убыток: доля суммы последних четырёх прибыльных закрытых сделок. Стоп исполняется как лимитная продажа с ценовым минимумом. |
| `TRADER_MAX_LOSS_BALANCE_PERCENT` | `0.5` | Ограничение риска от доступного баланса до появления прибыльной истории. |
| `TRADER_SIGNAL_MAX_AGE_SECONDS` | `300` | Возраст, после которого запрещён новый вход; открытая позиция продолжает обрабатываться. |
| `TRADER_SAME_ROUTE_REENTRY_COOLDOWN_SECONDS` | `300` | Пауза после закрытия сделки перед повторным входом в ту же пару на той же паре бирж; направление между биржами не имеет значения. `0` отключает правило. |
| `TRADER_SIGNAL_MAX_ATTEMPTS` | `5` | Максимум повторов временной ошибки сигнала. |
| `TRADER_SETTLEMENT_RETRY_SECONDS` | `15` | Интервал повтора незакрытой части продажи. |
| `TRADER_SETTLEMENT_MAX_WAIT_SECONDS` | `3600` | После этого остаток сохраняется как открытая позиция. |

## Тесты и запуск

Тесты используют локальные mock-ответы и не требуют API-ключей или ожидания задержки:

```powershell
python -m unittest discover -s tests -v
```

Или внутри образа проекта после его сборки:

```powershell
docker compose run --rm --build --entrypoint python trader -m unittest discover -s tests -v
```

Перед первым запуском скопируйте `.env.example` в `.env`, укажите ключи только с разрешением чтения, комиссии/профили, которые хотите моделировать, затем запустите:

```powershell
docker compose up -d --build mysql trader web
docker compose logs -f trader
```

Контейнер `trader` автоматически применяет аддитивные миграции и сохраняет старый баланс и историю. Веб-сводка сделок доступна на `/trader`; завершённые позиции и предполагаемые маршруты отображаются отдельно по статусу.

Для сервиса логируется причина отказа, временная ошибка, запуск симуляции, каждая продажа и незакрытый остаток в `log/trader.log`.

## Точность количества монет

В тренировочной симуляции размер покупки округляется вниз: если цена монеты ниже 1 USDT, покупается целое количество; если цена составляет 1 USDT или выше, сохраняется до 8 знаков после запятой. Это правило предотвращает показ и моделирование дробного количества для дешёвых монет и оставляет возможность покупать части BTC, ETH и других более дорогих активов. Значения округляются только для выбора размера позиции и отображения; цены и денежные расчёты сохраняют исходную точность.
