# Скринер

Общая база находится в корне проекта: `database.py` содержит подключение, инициализацию и операции с данными, а `schema.sql` — схему таблиц. Калькулятор и веб-часть используют те же таблицы.

Основные параметры приложения собраны с комментариями в корневом `config.py`. Чувствительные пароли остаются в переменных окружения; параметры скринера в MySQL-таблице `config` переопределяют соответствующие значения по умолчанию из Python-файла.

Файлы скринера разделены по задачам:

- `coinmarketcap.py` отправляет запросы CoinMarketCap и преобразует поля ответа.
- `filter.py` оставляет пары с объёмом `volumeUsd` за 24 часа от 300 000 до 500 000 USD включительно.
- `service.py` предоставляет `update_market_data()` для одного обновления.
- `fetch_markets.py` запускает одно обновление вручную.
- `main/worker.py` запускает цикл: сначала обновляет список, затем цены и процентные флаги; пауза берётся из `config.interval_minutes`.
- `main/__main__.py` запускает этот worker.
- `main/web.py` показывает только позиции с установленным `market_pairs.show_flag`; страница автоматически перечитывает БД каждые 15 секунд.

## Калькулятор

`main/calculator` получает perpetual-рынки валют, уже найденных скринером, и сохраняет
совпадения для списка `CALCULATOR_EXCHANGES` из `.env` (по умолчанию Binance, Bybit,
OKX и MEXC). Запрос выполняется один раз для каждого уникального `base_currency_slug`,
а результаты сопоставляются с исходными записями по `quote_symbol`.

Биржевые результаты хранятся строками в `calculator_market_pairs`, связанными с
исходной записью через `source_market_id`. Поэтому добавление биржи в `.env` не требует
добавлять новые колонки или менять схему таблицы. При успешном полном обновлении
старые результаты заменяются новыми; если запрос API завершается ошибкой, старые
данные этой валюты остаются в БД, а обработка продолжается для остальных валют.

Для каждой исходной пары калькулятор берёт лучшую по рангу запись на каждой бирже,
сравнивает цены минимум двух бирж по формуле `(максимальная цена - минимальная цена) /
минимальная цена * 100` и ставит `market_pairs.show_flag = 1`, если результат строго
от `CALCULATOR_SPREAD_LEVELS` (по умолчанию 0.85%, 1% и 1.5%). Панель позволяет независимо
включать диапазоны 0,85–1%, 1–1,5% и от 1,5%. Процент сохраняется в
`market_pairs.price_difference_percent`. Новый запуск скринера сбрасывает оба значения;
они выставляются снова при следующем запуске калькулятора.
Калькулятор пишет прогресс запросов и валют в журнал; пауза между стартами HTTP-запросов
задаётся `CALCULATOR_REQUEST_DELAY_SECONDS` (по умолчанию 0,2 секунды).
Параллельность управляется `CALCULATOR_WORKERS` (по умолчанию 4, допустимо 1–8).
Размер страницы задаётся `CALCULATOR_PAGE_SIZE` (по умолчанию 500); если API вернёт
меньшую страницу, калькулятор продолжит со следующей позиции по счётчику из ответа.
Пагинация по валюте останавливается, когда найдены все биржи из `CALCULATOR_EXCHANGES`.

Запуск одного обновления калькулятора:

```powershell
docker compose run --rm --build app python -m main.calculator.fetch_prices
```

В `market_pairs` сохраняются только пары, прошедшие фильтр. После успешной загрузки всего настроенного диапазона скринер удаляет из таблицы старые строки, чей объём больше не входит в этот диапазон. Если загрузка завершается ошибкой, очистка не выполняется.

Настройки диапазона API (`start`, `stop`, `limit`) и период обновления хранятся в MySQL-таблице `config`. Интервал по умолчанию — 2 минуты. JSON-ответы обрабатываются в памяти и не сохраняются.

Запуск из корня проекта:

```powershell
docker compose up --build
```

phpMyAdmin доступен на `http://localhost:8081`. Для разового обновления выполните:

```powershell
docker compose run --rm app python -m main.screener.fetch_markets
```
