# Docker окружение

Docker Compose запускает MySQL, phpMyAdmin, фоновый worker, веб-страницу и отдельный сервис трейдера. Worker сначала обновляет общий список рынков, затем цены настроенных бирж и процентную разницу. Публичные WebSocket-стаканы Binance, Bybit, OKX и MEXC остаются подключёнными во время REST-обновлений и следят за найденными спотовыми парами. После REST-цикла подписки обновляются; период задаёт `config.interval_minutes` (по умолчанию 2 минуты).

Скринер отправляет трейдеру JSON один раз, когда WebSocket-подтверждённая возможность непрерывно прожила не менее 3 секунд по умолчанию. Порог настраивается в `main/treider/config.py` через `MIN_OPPORTUNITY_LIFETIME_SECONDS` (или переменную `TRADER_MIN_OPPORTUNITY_LIFETIME_SECONDS`). Сообщения передаются через надёжную очередь `trader_signals` в MySQL; сервис трейдера ждёт новые сообщения и обрабатывает их. Модули `signals.py`, `queue.py`, `processor.py` и `service.py` разделяют формат сообщения, транспорт, бизнес-обработку и запуск сервиса. Сейчас обработчик пишет полученную связку в лог; размещение ордеров ещё не подключено.

Если очередь JSON-сигналов молчит 6 секунд, трейдер дополнительно проверяет свежие активные WebSocket-ситуации и ставит лучшую по порогу связку на обычную проверку входа. Проверяются только ситуации, обновлённые за последние 20 секунд; повторный вход по паре блокируется, пока по ней есть открытая тренировочная позиция. Интервал можно задать через `TRADER_ACTIVE_OPPORTUNITY_FALLBACK_SECONDS` (минимум 5 секунд).

WebSocket подтверждает возможность по исполнимой цене стакана: покупка по лучшему `ask`, продажа по лучшему `bid` на другой бирже. Для каждого порога из `CALCULATOR_SPREAD_LEVELS` сохраняется отдельный подтверждённый интервал. Если спред опускается ниже порога, но остаётся не ниже `CALCULATOR_SPREAD_RESET_PERCENT` (по умолчанию 0,8%), интервал сохраняется, его время продолжает накапливаться, а повторный JSON трейдеру не отправляется. Эпизод завершается, когда спред опускается ниже границы сброса. Активные и завершённые интервалы, время жизни и максимальный спред показываются на вкладке истории. Для публичных котировок API-ключи бирж не используются.

## Запуск

```powershell
docker compose up -d
```

Обычный запуск использует уже собранный образ; Compose соберёт его автоматически,
если образа ещё нет. После изменения кода или зависимостей пересоберите один раз:

```powershell
docker compose up --build -d
```

Веб-страница доступна на `http://localhost:36093`, phpMyAdmin — на `http://localhost:24760`. MySQL опубликован на порту `53587`. Эти внешние порты можно переопределить переменными `WEB_PORT`, `PHPMYADMIN_PORT` и `MYSQL_PORT` в `.env`. Вход в phpMyAdmin — пользователь и пароль MySQL из `.env`. Изменяйте диапазон, размер страницы и интервал в таблице `config`.

На странице `/market-units` коэффициенты для известных несовпадений тикеров заполняются автоматически из `config/market_unit_references.json`. Там сохранены официальные источники, дата проверки и, где доступны, сеть и контракт. Фоновый цикл `app` раз в 6 часов запрашивает метаданные через существующие API бирж и записывает только безопасные поля в `config/market_unit_proposals.json`. При отсутствии API-доступа, устаревшей проверке или несовпадении контракта таблица показывает соответствующий статус. Для новых неизвестных названий коэффициент не подставляется; числовой префикс даёт только предварительную подсказку. Совпадение контракта проверяется вместе с сетью, оно не подтверждает размер лота автоматически.

Кнопка «Подтвердить / сохранить» сохраняет выбранный пользователем коэффициент в прежний `config/market_unit_mappings.json`. Автопредложения не перезаписывают подтверждения. Предварительные NEIRO/NEIROCTO и BTTC/BTT на Bybit требуют ручной сверки исходного актива. Для отдельного обновления метаданных: `docker compose run --rm app python -m main.market_unit_proposals`. Используются только запросы чтения; без ключей соответствующая API-проверка останется недоступной.

На странице `/history` отображаются подтверждённые интервалы и их длительность, а также
счётчики начал интервалов по каждому порогу за последние 1, 12 и 24 часа. Снимки REST
хранятся 30 дней; интервалы WebSocket сохраняются в таблице `opportunity_lifetimes`.

Логи worker:

```powershell
docker compose logs -f app
```

Фоновый worker одновременно пишет журнал циклов в `log/updates.log` на хосте.
Файл ротируется при достижении 10 МБ; сохраняются пять предыдущих файлов.

Логи веб-сервера:

```powershell
docker compose logs -f web
```

Остановить контейнеры, сохранив базу:

```powershell
docker compose down
```

Данные MySQL хранятся в постоянном томе `arbitrajv2_mysql_data` и сохраняются при
пересоздании контейнера и команде `docker compose down`. Не используйте `docker compose down -v`,
если хотите сохранить базу: флаг `-v` удаляет том вместе с данными.

Настройки и схема базы находятся в корне проекта (`config.py`, `database.py`, `schema.sql`). Пароли и параметры запуска заданы в `.env`; интервал и диапазон скринера читаются из таблицы MySQL `config`. Для разового обновления только общего списка:

```powershell
docker compose run --rm app python -m main.screener.fetch_markets
```

Для разового обновления биржевых цен и процентных флагов:

```powershell
docker compose run --rm app python -m main.calculator.fetch_prices
```
